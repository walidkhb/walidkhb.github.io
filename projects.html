Platform Automation
Saudi bank · 2024–2026 · Riyadh

Automated Integration Delivery Platform

Integration ran on a legacy service bus, deployed by hand one environment at a time. I moved it to a container platform with Git as the single source of truth. Every release is versioned, each environment’s configuration has its own repository, and API publishing is automated.

Automated build and release now runs for 12 integration platforms on an engineering platform of 142 repositories, with about two minutes from merge to a running build, and 278 API products brought under Git control. Every change passes compliance checks before it can deploy, and production stays gated by approval. Releases are repeatable and traceable end to end, and they no longer depend on the person who knows the steps.

I then made it policy: every vendor and every modernisation programme delivers through the bank’s own source control, CI/CD and Cloud Pak for Integration pipeline—no vendor-owned tooling. The platform, not the supplier, decides how change reaches production.

New mandates and partners arrive every year. I led integration for more than twelve regulatory and partner programmes on the shared platform: judicial enforcement, treasury, credit-bureau data sharing, escrow, family banking, card operations and biometric verification.

I also led an architecture and security assessment of the corporate internet banking estate, ending in a prioritised remediation register. And I set the integration position in the managed-services contract and transformation RFPs, so integration service levels are defined by the bank.
