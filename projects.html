  • Created real-time monitoring dashboards with configurable alert thresholds for the risk team
  • Integrated with SAMA regulatory reporting for suspicious activity disclosure

07 — Operational Excellence

Zero-Downtime Modernization: Replacing the Engine Mid-Flight

Business Challenge

The bank's legacy integration middleware was unsustainable—expensive to maintain, impossible to scale, and couldn't support modern patterns. But it processed every core banking transaction, every card authorization, and every payment settlement. Replacing it meant rewriting the nervous system of a running bank without a single second of service interruption.

What I Delivered

  • Designed a strangler fig migration strategy: gradual traffic rerouting from legacy to modern platform
  • Built traffic management at the gateway: shadow mode (dual-write validation), canary routing (percentage-based cutover), and instant rollback
  • Migrated in priority waves: non-critical flows first, then batch processing, then real-time transactions
  • Redesigned integration patterns during migration—SOA and microservices architecture, not lift-and-shift
  • Achieved complete migration with zero service interruption to customers or internal operations

Unified Customer Communication Platform

Business Challenge

Customers received duplicate messages, inconsistent branding, and had no way to manage preferences. What I Designed

  • Reliability engineering: at-least-once delivery with idempotency, dead-letter queues, and exponential retry

Istithmar Capital (ICAP) needed to programmatically settle mutual fund redemption proceeds into SAIB customer accounts in real time. The existing process was a manual daily file exchange—slow, error-prone, and incapable of supporting the growth in fund transaction volumes. The integration had to bridge a modern REST API with a legacy AS/400 core banking system speaking fixed-length binary messages over IBM MQ.

Organizational Change

This project established the template for how SAIB approaches all B2B API integrations. Before this, every partner integration was a bespoke effort with no standardized security model, no reusable patterns, and no governance. After this, SAIB had a repeatable B2B integration model with defined security profiles, documented patterns, and a governance process that new partner teams could follow.

11 — SAMA Payment Schemes & Real-Time Settlement

Payment Hub: IPS, BPS & SADAD Core Banking Integration

Business Challenge

SAMA mandated adoption of the Instant Payment System (IPS)—requiring Saudi banks to process payments in real time with immediate settlement. SAIB's payment hub (TMS/X eMcREY) needed an ESB integration layer to connect to the ICS core banking system for three critical payment schemes: IPS (instant), BPS (bulk), and SADAD (biller). The challenge was building a two-step verify-and-post protocol that holds funds atomically while maintaining the bank's regulatory compliance posture.

Organizational Change

This project established the payment integration operating model at SAIB. It defined clear domain boundaries: the Payment Hub owns payment orchestration and scheme routing; Core Banking owns account balances and ledger entries; the ESB owns protocol transformation and resilience. These boundaries, documented in domain specifications, eliminated the ownership confusion that had delayed previous payment initiatives.

Architecture & Standards Applied

TMS/X Payment Hub (REST/JSON)
→ SAIB API Gateway
→ ESB (IBM ACE 12) — two-step protocol orchestration
→ ICS Core Banking (IBM MQ binary AP2154-2)

Step 1: POST /payments/verify (501500) → Fund verification + hold
Step 2: POST /payments/{id}/post (501510) → Release hold + commit

Schemes: IPS (ISO 20022), BPS (ISO 20022), SADAD (Proprietary+ISO 20022)
10 REST endpoints across Payments, Accounting, Accounts, Customers

What Was Delivered

  • 10 REST API endpoints: payment verify, post, status, list; direct accounting; balance inquiry; transaction history; customer info; fee inquiry
  • Two-step atomic protocol: verify (creates hold) → post (releases hold + posts transaction) with dual-mode support (PSTTRX / HLDRMV)
  • Full ISO 20022 messaging alignment for IPS and BPS payment schemes
  • SADAD biller integration for government and commercial bill payments
  • Complete deliverables: 10 documents including Proposal, Plan, FDD, HLD, LLD, Backend Spec, OpenAPI, and IPS/BPS/SADAD function design documents
  • Domain boundary documentation establishing ownership between Payment Hub, Core Banking, and ESB

Institutional impact: This is SAMA-mandated infrastructure. The domain ownership model and payment integration patterns established here will govern every future payment scheme the bank adopts. The operating model ensures regulatory compliance is structural, not ad-hoc.

12 — Enterprise Standards & Governance

SAIB Integration Framework: 10 Enterprise Standards

Business Challenge

Every integration at SAIB was built differently. Different teams used different patterns, different security models, different error handling, different documentation formats. There was no institutional standard. Code reviews couldn't enforce quality because there was no agreed definition of quality. New team members had no reference architecture. Regulatory audits required collecting evidence from dozens of inconsistent implementations.

Organizational Change

I authored and established a comprehensive integration framework—10 non-negotiable standards documents that govern all integration work at SAIB. This is not documentation for documentation's sake. These are enforceable standards embedded into the development lifecycle, review gates, and CI/CD pipelines.

The 10 Standards

  • 01 Integration Principles — Domain ownership, thin ESB mediation, security perimeter, idempotency, replaceability
  • 02 API Standards — REST/OpenAPI 3.1, URL structure, resource naming, pagination, versioning (Richardson Maturity Level 3)
  • 03 Security Standards — FAPI 2.0 profiles, OAuth 2.0/OIDC, JWT/JWS, mTLS, TLS 1.3, DPoP, PKCE, PAR, JARM
  • 04 Integration Patterns — 7 canonical patterns: Sync REST, ESB Mediation, Async Events, ISO 20022, Open Banking TPP, File/SFTP, Webhooks
  • 05 Documentation Standards — Mandatory templates, review gates, governance checkpoints
  • 06 Observability Standards — OpenTelemetry, W3C Trace Context, SLIs/SLOs, Prometheus metrics, alerting
  • 07 Error Handling Standards — RFC 7807 Problem Details, circuit breakers (Resilience4j), idempotency keys, retry logic
  • 08 Data Standards — ISO 8583, ISO 20022, IBAN validation, field naming conventions
  • 09 Testing Standards — Contract testing, integration testing, security testing, test environments
  • 10 Governance — Architecture Decision Records (ADRs), integration registry, review gates, compliance checkpoints
